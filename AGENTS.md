# AI Usage Record

AI assistance was used to draft the project structure, Java classes, tests, and decision notes for this shopping basket assignment. The generated code was reviewed against the assignment requirements, adjusted for validation and BigDecimal money handling, and prepared for verification with Maven tests.

AI assistance was also used to add the collections and stream pipelines order-summary deliverable. The order model, customer key, immutable summary result, stream-based filtering, sorting, totals, grouped customer revenue, runnable example, tests, and decision notes were reviewed against the deliverable requirements.

The base environment did not include `java`, `javac`, or `mvn`, so portable OpenJDK 17 and Maven archives were installed under `/tmp/codex-java-tools` for local verification. The project was then tested with `mvn test`, and the runnable demo was checked with `mvn exec:java`.

AI assistance was also used to build the Safe Order Importer deliverable (exceptions, resource safety, and logging) in the new `com.fedstack.importer` package. The generated exception hierarchy, `Order`/`ImportResult` models, `OrderImporter` (try-with-resources, exception translation, SLF4J logging), the runnable `OrderImportDemo`, and the learner tests (including the `CloseTrackingReader` test double) were reviewed against the deliverable's requirements — particularly that malformed-row and read-failure messages never repeat full row contents, that causes are preserved through translation, and that the input source closes on every path. Design choices (package boundary, `Reader`-based input, exception hierarchy shape) were confirmed with the learner before implementation rather than assumed.

The environment for this deliverable also lacked a working `javac` (only a headless JRE was preinstalled, and `sudo apt-get install` was unavailable without a terminal for authentication), so a portable OpenJDK 17 archive was downloaded to the session scratchpad and used via `JAVA_HOME` to run `mvn test` and `mvn exec:java` for verification; no system files were modified. All 44 tests (13 new, 31 pre-existing) passed, and the `pom.xml` `exec.mainClass` property was parameterized so both `BasketDemo` (default) and the new `OrderImportDemo` remain runnable via `-Dexec.mainClass`.
